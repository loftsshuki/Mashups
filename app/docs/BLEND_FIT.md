# Blend Fit v1

Blend Fit is available before Generate in `/create` and as a local-file checker at `/create/blend-fit`. It evaluates a vocal/lead section against an instrumental/backing section at a proposed target tempo and original pitch. It does not separate stems, apply edits, render an uploaded pair, or estimate the probability of listener approval.

## What is measured

- Audio is decoded locally by OfflineAudioContext at 11,025 Hz. A selected 8–30 second excerpt is sent to a disposable Web Worker. No audio, filename, or results are uploaded or persisted. The checker has a `ph-no-capture` boundary to exclude its DOM and interactions from the app's PostHog autocapture and replay, following [PostHog privacy controls](https://posthog.com/docs/session-replay/privacy). General page analytics can still run. The file limit is 25 MB and decoded duration limit is 10 minutes. The browser must decode the full input before selecting an excerpt, so short source files are preferable on phones.
- Tempo uses positive RMS changes at roughly 100 frames/second and normalized autocorrelation over pulses from 60–180 BPM. Competing non-octave peaks, weak periodicity and insufficient onsets return unknown. It reports a pulse estimate, not a verified beat/downbeat grid. An octave interpretation is always identified for confirmation. A producer can enter a checked source BPM; the result explicitly identifies this as user input.
- Tonal evidence uses a Hann-windowed 4096-point FFT, interpolated spectral peaks from 65–2000 Hz, 12 pitch classes, and major/minor key-profile correlations. Weak, noisy, sparse, off-tuning or unstable evidence remains unknown. A key is exposed only when at least four pitch classes contribute, enough frames have tonal peaks, correlation and runner-up margin are sufficient, and at least three of four section windows agree. These are conservative engineering heuristics, not calibrated confidence probabilities. This is not vocal fundamental-frequency estimation or chord-by-chord compatibility.
- Signal checks measure RMS, sample peak and near-full-scale sample fraction in the analyzed, resampled channel. They do not measure LUFS, true peak, separation quality, post-stretch artifacts or mix balance. The louder channel is analyzed to avoid stereo phase cancellation; stereo quality is unassessed.

Method references: [librosa chromagram documentation](https://librosa.org/doc/0.11.0/generated/librosa.feature.chroma_stft.html), [librosa tempogram documentation](https://librosa.org/doc/0.11.0/generated/librosa.feature.tempogram.html), [MDN OfflineAudioContext](https://developer.mozilla.org/en-US/docs/Web/API/OfflineAudioContext), [MDN Web Workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers). The browser implementation is small, custom DSP; it does not run librosa or claim equivalent accuracy.

## How guidance works

No overall numeric score or success percentage is produced. Stretch changes use `(targetBpm / sourceBpm - 1) × 100`, separate from musical pitch. Changes above 6% ask for an audition; above 15% indicate a difficult pairing. These are initial usability thresholds, not universal audio-quality limits. Large measured problems take priority over unknowns; otherwise missing tempo or key evidence gives Uncertain. Known tonal differences give a caution rather than declaring a creative combination impossible.

Promising means the measured tempo/key checks support an initial experiment. Beat/bar alignment, phrasing and rendered sound remain visibly unverified even in that state. Same or relative keys do not establish chord compatibility. No automatic pitch-shift prescription is issued from uncertain evidence. A result never prevents experimentation or changes the catalog renderer's supported recipe settings.

Source, role, section or target changes invalidate results immediately. Abort controllers belong to individual operations; cancelled workers are terminated. Replaced files revoke object URLs. Analysis errors do not turn into fabricated C-major/120-BPM results. The unused legacy Smart Match panel, fake key detector, approximate-LUFS routine and percentage badge were removed. Catalog metadata checks are labeled prototype recipe checks; the audio checker is separate from the catalog renderer. Demo ingredients are the actual separately synthesized lead/backing of the selected catalog pair, explicitly labeled as demos.

## Validation and next milestone

Automated tests use original synthetic signals: unsnapped click tempos, silence, deterministic noise, transposed diatonic melody, selected-region extraction and anti-phase stereo. Decision tests cover missing measurements, stretch ratios, symmetric relative keys and octave ambiguity. Browser tests exercise the real decoder/worker, local file replacement, invalid excerpts, cancel/retry, source-change invalidation and the creation entry point on desktop and mobile viewports. These checks establish implementation behavior, not real-music recommendation accuracy.

Before a probability model: collect rights-appropriate, full musical phrases and rendered candidates covering rap, sung vocals, changing chords, drifting tempo, clean and imperfect separation. Have multiple listeners rate blinded examples against a defined outcome such as “usable without manual correction.” Split evaluation by source song/artist to avoid leakage; assess calibration and failure rates on unseen songs. Add downbeat/chord/vocal-pitch analysis only when it improves those held-out outcomes. Preserve abstention for inconclusive material and producer overrides.
