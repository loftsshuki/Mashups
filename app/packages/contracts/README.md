# @mashups/contracts

Framework-neutral contracts shared by the Mashups web application and a future Expo client.

The package intentionally contains no React, Next.js, Supabase, filesystem, or server-only imports. It defines:

- Green Room arrangement IDs.
- Funnel event names.
- Rights, audio-quality, catalog, and pilot metric types.
- Canonical web and native creation links.
- Private project recipes, stable IDs, revision receipts, and resume links.

Example:

```ts
import { buildGreenCreatePath, buildGreenNativeLink } from "@mashups/contracts"

buildGreenCreatePath({ leftId: "signal-bloom", rightId: "heat-map" })
buildGreenNativeLink({ leftId: "signal-bloom", rightId: "heat-map" })
```

Web, iOS, and Android are in the first release programme. Native implementation
starts alongside the web loop as shared interfaces become ready; user-count and
retention thresholds do not gate that work. See `docs/PLATFORM_BUILD_PLAN.md`.

`GreenProjectInput` describes the body of `PUT /api/green/projects`.
`expectedRevision: 0` creates a project; later saves use the last confirmed
`GreenSavedProject.revision`. An identical retry returns that same receipt.
Conflicts require a new copy; never silently replace the revision with a newer
one and overwrite another device's edits. IDs are UUIDs generated by the client.

Web calls use the authenticated session cookie. Native calls may provide a
Supabase access token in `Authorization: Bearer …`; the server verifies it before
choosing the project owner. The prototype recipe and browser audio cache are
separate: the API stores no rendered audio and grants no public playback rights.
